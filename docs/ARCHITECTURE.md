# Architecture

```text
UI (TanStack Start, React, Tailwind)  ── routes/, components/
        │ typed boundaries
core/   ├─ types.ts               domain model (platform-agnostic)
        ├─ library/repository.ts  LibraryRepository  → native SQLite (future)
        ├─ playback/adapter.ts    PlaybackAdapter    → Capacitor plugin → Kotlin MediaSessionService + Media3 ExoPlayer (future)
        └─ platform/capabilities  honest capability report
```

- Web preview installs `EmptyLibraryRepository` and `UnavailablePlaybackAdapter`. They return empty data / reject commands; they never simulate playback with browser audio or timers.
- The Android bridge will call `setLibraryRepository` / `setPlaybackAdapter` at startup.
- Discovery: MediaStore scan + Storage Access Framework folder import (Kotlin).
- SQLite is the offline source of truth for tracks, albums, artists, playlists, lyrics, favorites, history, preferences.
- Playback position, queue and state are owned by the native player and pushed to the UI via `subscribe`.
- A future iOS client implements the same two interfaces (AVFoundation / MPNowPlayingInfoCenter).

## Verifiable in browser vs device
- Browser: layout, navigation, accessibility, empty/error states, data-flow wiring.
- Device only: scanning, playback, background audio, notification/lock-screen, Bluetooth/headset controls, SQLite.

## Android shell (M2)
- Capacitor 8.6.0 (`@capacitor/core`, `@capacitor/android`, `@capacitor/cli`). appId `app.obsidiansound.player`, name "Obsidian Sound". Config: `capacitor.config.ts`. Native project: `android/` (minSdk 24, target/compile 36), committed to the repo.
- The web app is SSR on the web. For the device, `CAPACITOR_BUILD=1` switches TanStack Start to SPA mode; `scripts/prepare-capacitor-web.mjs` copies `dist/client` to `dist/capacitor` and renames `_shell.html` to `index.html`. Capacitor copies that into `android/app/src/main/assets/public` (git-ignored, regenerated by sync).
- Startup: `src/core/bootstrap.ts` runs client-side from the root route. It detects the runtime via the injected `window.Capacitor` bridge (no import on the web). On Android only, it dynamically imports the SQLite plugin, runs migrations, installs `SqliteLibraryRepository`, then marks `offlineDatabase` available. Any failure leaves it unavailable.

## Local database
- Plugin: `@capacitor-community/sqlite` 8.1.1 (peer `@capacitor/core >= 8`). Used only through `SqlExecutor` (`src/core/db/executor.ts`), adapter in `src/core/db/capacitor-sqlite.ts`.
- Migrations: `src/core/db/migrations.ts`, append-only, versions 1..n. `migrate()` enables `PRAGMA foreign_keys`, records versions in `schema_migrations`, applies each pending migration in its own transaction, is safe to run every launch, and refuses a database newer than the app.
- Schema v1: artists, albums, tracks, track_artists (role, position, source), track_field_overrides, playlists, playlist_tracks, lyrics (+ lyric_lines, lyric_words), favorites, playback_history, app_preferences.
- Provenance: `tracks` columns are embedded tags only (rescans may refresh them). Manual edits live in `track_field_overrides` and in `track_artists` rows with `source='manual'`; rescans never write those. Effective value = manual ?? embedded.
- Identity: text IDs generated by the app; audio referenced by `source_uri` (content URI) plus optional `mediastore_id` and `content_hash`. Never absolute paths.
- Lyrics: `kind` static | line_synced | word_synced, `source` manual | lrc_import | embedded_tag, `offset_ms`, one preferred per track. No lyric content is shipped.
- Tests run the real migrations against `node:sqlite` in memory (`src/test/db.test.ts`).
